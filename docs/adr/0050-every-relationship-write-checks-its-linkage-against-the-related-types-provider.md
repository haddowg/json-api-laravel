# Every relationship write checks its linkage against the related type's provider

Linkage to a resource that does not exist was only refused when its type had a provider of the application's own, a global scope hid it, or its id couldn't be decoded: otherwise an Eloquent to-one associated a keyed blank and stored a dangling key, a to-many dropped the member, the in-memory persister cleared or dropped it, and a `fillUsing()` hook or a declared `MorphToMany`'s link rows stored the id as sent. Every relationship write now checks each id it names against its type's provider before anything is stored, the reference providers included, on create, update, every relationship endpoint mode and atomic operations, and refuses one the provider does not serve with `404 RESOURCE_NOT_FOUND`, whether no row holds it or a scope hides it. A remove is checked too, so the package and the Symfony bundle agree, while removing an existing row the parent doesn't hold still changes nothing. One routine does it, asking each type once per write through `AdmitsIdsInterface` or `FetchesManyInterface`, and through `fetchOne()` when the provider has neither or for an id the batch left out. On Eloquent that is one key-only query per related type, on top of the persister's own finds. This replaces the last sentence of ADR 0013, which trusted the reference providers as they were, and a type no provider serves still has nothing to check against.
