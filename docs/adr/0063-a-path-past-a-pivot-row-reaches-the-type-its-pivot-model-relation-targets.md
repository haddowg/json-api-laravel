# A path past a pivot row reaches the type its pivot model's relation targets

A `->through()` path can go on from a pivot row, as in `pivot.addedBy`, but a pivot row has no type, so core asks the provider which type each of its relations reaches. The Eloquent provider answers from the pivot model a `belongsToMany` names with `->using()`, the model the `pivot.`-prefixed filters already walk, and names the one type it serves with the model that relation targets, refusing at boot when none or several do, because the reached type's scope, read gate and encoder have to apply and a guess would apply the wrong ones. A leading `pivot` runs only where the relation's query has joined the row, as the `pivot.` column filters do, while a mid-path `pivot` is one more `EXISTS` over the join table with the member it links kept to the rows its model's global scopes admit.
