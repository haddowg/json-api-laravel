# Pivot hooks render in the serializer, and the in-memory provider renders only computed pivot fields

A pivot field read through a hook, a computed one or a stored one with `extractUsing()`, is evaluated by the pivot meta serializer from the parent, each rendered member and the member's stored values, through core's `hookedPivotValues()`, rather than by the data provider beside the stored pivot columns. The serializer already sees every member on the related endpoint, the relationship endpoint and a mutation's linkage, so one place covers them all. The in-memory provider keeps its boundary of storing no pivot rows, but computed fields don't depend on storage, so it renders the computed members of `meta.pivot` with empty stored values and never a stored member, on all-computed and mixed relations alike. A relation whose fields are all computed needs no pivot columns on Eloquent and writes its join through the id-only sync.
