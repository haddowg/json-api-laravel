# A filter is refused only by checks that decide without a row

One filter matches every candidate row at once, so the policy checks that guard a relation it reaches through are asked with no row to decide against. A policy method or Gate ability that takes the user alone answers for every row, and refusing it is a `403`. A `view` method that takes the row is left to the related type's scope, as it is on that type's own collection, while a relation's read permission that takes the parent refuses the filter for everyone, since no scope stands behind it and matching through it would show what the permission hides. Telling the two apart by the callable's parameter count reads what the author wrote rather than calling the check with a stand-in row and guessing from the answer.
