# describedby finds the document route by its controller

An app that turns off route registration and routes `OpenApiController` itself, under its own route names, used to lose every `describedby` without a sign, because the document URL was generated from the package's route names only. When those names aren't registered the package now looks for a named `GET` route whose action is `OpenApiController` and whose `server` parameter picks the server, scanning the routes once at `artisan optimize` (or once per process without a stored result) because the scan is too costly per request. When no route serves a server's document while the expose gate is open and no `document_url` is set, the optimize step logs a warning rather than failing, since `describedby` is optional and a closed gate is the documented way to have none. The lookup order and the warning match the Symfony bundle's (its ADR 0135).
