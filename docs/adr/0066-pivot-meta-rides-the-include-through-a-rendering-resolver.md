# Pivot meta rides the include through a rendering resolver

A pivot relation's `meta.pivot` belongs to a parent and a member, and a relation reached through `?include` is built by a resource whose resolver is the server, which knows neither. A read's document therefore resolves its serializers through `PivotRenderingResolver`, which decorates every type that reaches a pivot relation so its relationships are built back through the same resolver at every depth, and binds each parent's pivot relation to a `PivotMetaSerializer` that reads the stored values off the pivot row the include's query already hydrated on the member. Reading them off the member, rather than batching a separate pivot map per level as the bundle does for the primary type, keeps the include walk the only place that queries and gives every depth the same path.
