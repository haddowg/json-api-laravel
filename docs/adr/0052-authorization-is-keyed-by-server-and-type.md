# Authorization is keyed by server and type

Two servers may expose the same type through different resource classes, and the authorizer used to key its config by type alone, so whichever class discovery read last lent its `policy:` and ability renames to both servers. We now key it by server and type and have every check, the endpoints, the related type's gates, the `view{Relation}` convention, actions and the OpenAPI projection, read the entry of the server the request is on. A server whose class declares nothing falls through to the Gate rather than borrowing another server's entry, and the Gate's model policy stays per model on purpose. A check with no routed request reads the server the operation carries, recognised by its resource registry, and otherwise the `default` server.

The declarative response headers and the tags an action inherits from its mount type had the same last-wins keying, so they are keyed by server and type too. A server whose class declares none gets the global `jsonapi.defaults` headers and the default tag. The OpenAPI document does not describe the cache or deprecation headers on either server, in this package or the bundle, so nothing there changes.

The id encoder the Eloquent provider and persister decode wire ids with was also read off the first class declaring a type. It now comes from the class of the server the operation runs on, bound by the handler at the start of each dispatch.
