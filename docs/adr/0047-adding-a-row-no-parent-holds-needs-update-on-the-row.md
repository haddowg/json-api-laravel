# Adding a row no parent holds needs update on the row

ADR 0042 let a row with no parent move into any parent the caller could update, while the Symfony bundle's ADR 0137 requires the row's own update gate for it, so the two answered the same request differently. We adopt the bundle's rule: on a relation where a row has one parent, adding or replacing with a row that no parent holds needs the `update` ability on the row, or the write is a `403`. Linking the row changes it (its foreign key is set), and setting the same foreign key through the row's own to-one would need that ability, so this refuses only links the caller couldn't make another way. Both persisters now report such a row with a null owner, which the handler already checked against the row alone, and a row the parent already holds needs nothing more.
