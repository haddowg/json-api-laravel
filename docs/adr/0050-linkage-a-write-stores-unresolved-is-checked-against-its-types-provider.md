# Linkage a write stores unresolved is checked against its type's provider

A `fillUsing()` hook gets bare identifiers and a declared `MorphToMany` writes them onto link rows, so no persister ever looks the targets up, and an id naming no Eloquent or in-memory row was stored and answered `201` or `200`, where an application's own provider already refused it. Each id such a write names must now be one its type's provider serves, the reference providers included, checked before the hook runs or a row is written and refused with the same `404`. The check asks each type once through `AdmitsIdsInterface` or `FetchesManyInterface` where the provider offers either, and through `fetchOne()` otherwise or for an id the batch left out. A remove isn't checked against a reference provider, matching every other relation, and a type no provider serves has nothing to check against.
