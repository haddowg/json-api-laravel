# The handler validates a write's declared meta before it hydrates

Core lets a type declare a write's top-level meta and its resource objects' meta, and closes every declared meta object, pivots and identifier meta included. The CRUD handler and the action invoker validate each write's meta with the same `illuminate/validation` rules an attribute gets, rebased from `/data/attributes` onto `/meta` or `/data/meta`, so a member is refused, typed and normalized exactly as an attribute is, and put the typed values on the request as core's WrittenMeta, so the hydrator, the write events, the hook context and an action's context read one source. Only `app.debug` checks rendered resource objects and linkage identifiers against their declarations, in the controller and for each atomic result, and route registration and `jsonapi:optimize` refuse a misdeclaration, a `getMeta()` override beside `resourceMeta()` and request meta on a raw-body action, since none of them can be served as declared.
