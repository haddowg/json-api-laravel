# A path through relations reads only what the related models' scopes admit

A filter or sort declared with `->through()` reveals the values and order of the rows its path reaches, so it follows ADR 0059's rules: a filter is one `whereHas` per relation and a sort a correlated subselect per to-one relation, each built from the related model's own query so its global scopes hide rows at every hop, a request naming one through a relation the caller may not read answers the related endpoint's `403`, and a default reads no row through such a relation instead. A sort reads its cursor boundary from the selected subselect rather than the model's relations, so the token and the keyset `WHERE` agree on scoped rows, and an Eloquent query can't apply the scope of a type another provider serves, so `jsonapi:optimize` refuses a hop into one rather than letting it match rows that provider hides.
